# Stage 5: Data Pages & Matrix Views Migration

## Goal
Migrate all 9 operational data pages to the standardized design pattern (`PageHeader` + `TabNav` + `Card` + `Toolbar` + `DataTable`/`MatrixGrid`), eliminating all local style constants.

## Execution Order
Run the prompt below sequentially for each page:
1. `RosterPage.tsx` *(Reference Matrix Page)*
2. `PatientsPage.tsx`
3. `ClinicalPage.tsx`
4. `LabPage.tsx`
5. `PharmacyPage.tsx`
6. `InventoryPage.tsx`
7. `BillingPage.tsx`
8. `HandoverPage.tsx`
9. `CommunicationsPage.tsx`

## Prompt to AI Agent (Apply Per Page)
Refactor `apps/desktop/src/pages/XxxPage.tsx` to match the target UI standard using `@hims/ui` and design tokens, deleting all bottom-of-file inline style constants.

1. **Page Structure:**
   - **Header:** Integrate `PageHeader` containing page title, descriptive subtitle, status pill badge (if applicable), and primary/secondary action buttons (e.g., `Edit Manually`, `Auto-Generate`, `Export`, `Create New`).
   - **Sub-Navigation:** If the page has sub-views or modes, implement `TabNav` with underline active indicators.
   - **Content Wrapper:** Wrap data in `Card` primitives. If the view requires filters or selectors, include a card header toolbar (e.g., viewing mode hint on left, date/month picker dropdown on right).
2. **Data Presentation:**
   - Replace ad-hoc tables with `DataTable` / `MatrixGrid`.
   - If rendering shift matrices or status lists, use `ShiftBadge` (`Day`, `Night`, `Aft`, `Off`) or `StatusBadge` chips.
   - Ensure wide tables support horizontal scrolling with sticky identity columns (e.g., Staff Name / Role).
3. **Modals & Forms:**
   - Convert all local modals to the `@hims/ui` `Modal` primitive using `FormField`, `Input`, `Select`, and modal footer actions.
4. **State Handling:**
   - Loading: Centered `Spinner` inside data containers.
   - Empty: `EmptyState` component with icon, description, and call to action.
   - Error: Structured alert card with danger styling and retry button.
5. **Preservation:** Keep all API interactions, data queries, state transitions, and accessible text identical.

## Verification Steps
- Run `pnpm typecheck && pnpm lint && pnpm test && pnpm build` after completing each individual page before advancing to the next.
